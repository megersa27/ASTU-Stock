🚀 Sprint 2 — Day 2: User Flow Design
Welcome back! Yesterday we learned what UX/UI design is and created our UX Design Brief.
Today we move to the next step:
How does a user move through the system to accomplish a goal?
This is called a User Flow.

1. What is a User Flow?
A User Flow is the sequence of steps a user follows to complete a task in a software system.
For example, our Store Keeper wants to receive new stock.
We don't simply say:
"There should be a Receive Stock page."
We ask:
What does the user do from the moment they start until the task is completed?
Login
  ↓
Dashboard
  ↓
Receive Stock
  ↓
Select Item
  ↓
Select Supplier
  ↓
Enter Quantity
  ↓
Review
  ↓
Confirm
  ↓
Stock Updated
  ↓
Success
That's a user flow.

2. Why is User Flow Important?
Imagine we skip user flows and immediately design Figma screens.
We might create:
Dashboard
Inventory
Receive
Issue
Reports
...
But we don't know:
    • What happens after clicking Receive? 
    • What information is required? 
    • What if the quantity is invalid? 
    • What if the item doesn't exist? 
    • What happens after successful submission? 
    • Can the user cancel? 
    • What happens when an error occurs? 
User Flow forces us to think about those questions before UI design.
So:
Requirement
     ↓
User Flow
     ↓
Wireframe
     ↓
UI

5. User Flow Notation
We'll use simple symbols.

       ○

   [Screen/Action]
       ▭

   <Decision>
       ◇

       ↓
   Direction
For example:
      ○ Start
        ↓
   ▭ Login Screen
        ↓
   ◇ Credentials valid?
      /       \
    No         Yes
    ↓           ↓
▭ Show Error  ▭ Dashboard
                ↓
               ○ End
You don't need complicated diagram notation yet.

6. Flow 1 — Login
Let's start with the simplest flow.
Goal
A user wants to access the system.
○ Start
   ↓
▭ Open Login Page
   ↓
▭ Enter Email
   ↓
▭ Enter Password
   ↓
▭ Click Login
   ↓
◇ Are credentials valid?
   │
   ├── NO ──→ ▭ Show Error
   │             ↓
   │         ▭ Try Again
   │             │
   │             └──────→ Login
   │
   └── YES ──→ ▭ Identify User Role
                    ↓
                ▭ Dashboard
                    ↓
                    ○
Why do we have the decision?
Because real software doesn't have only a "happy path."
We need to consider:
Success
Failure
This is one of the most important lessons in user-flow design.

9. What if something goes wrong?
This is where your UX becomes more realistic.
Scenario A — Quantity is invalid
Quantity: -10
       ↓
❌ Invalid quantity
User corrects it.

Scenario B — Supplier doesn't exist
The user should be able to:
Supplier
[ Select Supplier ▼ ]

+ Add New Supplier
This is a UX decision we may consider during wireframing.

Scenario C — Network/server error
Imagine the Store Keeper clicks:
Confirm Receipt
but the server doesn't respond.
The user shouldn't see:
Something went wrong.
with no useful information.
Instead:
⚠ Unable to save the transaction.

Your stock was not changed.
Please check your connection and try again.

[Try Again]
[Cancel]
This is error-state UX.
We'll design these states later.

11. Important Business Rule
Remember our SRS:
BR-003: Stock cannot be issued when the requested quantity exceeds available stock.
Therefore our UX must reflect that rule.
Suppose:
Available Stock = 15
User enters:
Issue Quantity = 20
The UI should immediately help the user:
Available: 15

Quantity:
[ 20 ]

⚠ Only 15 items are available.

[Issue Stock]
The button could be disabled or submission rejected.
This is an excellent example of how:
Business Rule
       ↓
UX Decision
       ↓
UI Behavior
