1. What is a Prototype?
A prototype is an interactive version of your UI design.
Instead of just looking at:
Inventory
[ + Add Item ]
the user can actually click:
Inventory
      ↓
[ + Add Item ]
      ↓
Add Inventory Item
      ↓
Fill form
      ↓
[ Save Item ]
      ↓
Inventory
You're simulating how the real application will work.
Important distinction
Your Figma prototype is not the actual application.
Figma Prototype
      ↓
Simulates interaction
      ↓
Helps test UX
      ↓
Then later...
      ↓
React + Backend
      ↓
Real application

2. Why do we prototype before coding?
Imagine you start coding the Inventory page.
After two weeks, someone says:
"The Add Item button should actually be on the other side."
You now have to change:
    • React components 
    • CSS 
    • routing 
    • possibly backend interaction 
    • tests 
But if you discover the problem in Figma:
Change design
     ↓
Few minutes
That's why UX design can save development time.

🧪 14. Now comes the most important part: Testing
Don't just click through it yourself.
Pretend you're a new employee at ASTU who has never seen your system.
Give yourself a task:
"Add 50 Printer Papers to the inventory."
Now try to complete it using only the prototype.
Observe yourself.
Ask:
Question 1
Can I immediately understand where to go?
Dashboard → ?
Question 2
Can I easily find Inventory?
Question 3
Is Add Item obvious?
Question 4
Do I understand what information the form requires?
Question 5
After clicking Save, do I understand what happened?
Question 6
Can I easily cancel?

🧠 16. This teaches you something important about SDLC
Notice what we're doing:
Design
  ↓
Prototype
  ↓
Test
  ↓
Find problem
  ↓
Improve design
  ↓
Prototype again
This is much cheaper than:
Code
  ↓
Test
  ↓
Find UX problem
  ↓
Rewrite code
This is one reason modern software development doesn't mean:
"Write all the code first."

🤖 17. Use AI AFTER your own testing
Since you've been using AI as a learning assistant, now you can ask AI to critique your design.
For example, take screenshots of your prototype and ask:
"Act as a senior UX designer. Review this ASTU Stock Management System prototype. Identify usability problems, unclear interactions, accessibility issues, unnecessary complexity, and improvements. Do not redesign it completely; explain the problems and why they matter."
That's much better than asking:
"Make my UI better."
Because now you are making the design decisions.
